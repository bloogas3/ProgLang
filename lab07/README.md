## Задание 1 

### Условие

Оцените работу следующих фрагментов программ. Какие из них обладают неоднозначным поведением? Почему?

```cpp
int x = 10, y = 3;
cout << min(x = 15, x + y);
```

```cpp
int x = 10, y = 3;
x = 15, y += x, x += y;
```

```cpp
int x = 10, y = 9;
if (x > y++ && y++ > 9)
    cout << "yes" << endl;
cout << y;
```

### Решение

**Первый фрагмент.** В C++ не задано, какой аргумент `min` вычислится первым, поэтому возможен вывод `13` или `15`:

- если сначала вычислить `x + y`, получится `10 + 3 = 13`, затем `x` станет `15`, и `min(15, 13) = 13`;
- если сначала выполнить `x = 15`, выражение `x + y` даст `18`, поэтому `min(15, 18) = 15`.

У обоих вариантов в конце `x = 15`. **На один конкретный результат первого фрагмента полагаться нельзя:** порядок вычисления аргументов в этой записи не фиксирован. Чтобы убрать неоднозначность, следует разнести действия по разным строкам.

**Второй фрагмент.** Оператор `,` упорядочивает действия слева направо:

1. `x = 15` → `x = 15`, `y = 3`;
2. `y += x` → `y = 18`;
3. `x += y` → `x = 33`.

Итог: **`x = 33`, `y = 18`**. Неоднозначности нет.

**Третий фрагмент.** Логическое `&&` вычисляет левую часть раньше правой, а `y++` сначала отдаёт старое значение и только потом увеличивает переменную:

1. `10 > 9` → истина, `y` становится `10`;
2. `10 > 9` → истина, `y` становится `11`;
3. выполняется вывод `yes`, затем числа `11`.

Вывод:

```text
yes
11
```

Неоднозначности нет.


## Задание 2 

### Условие

Как записать следующие строки программы на C++ в виде одного выражения? Приведите несколько способов, в том числе с использованием операторов инкремента.

```cpp
x = x + 1;
z = z + 2 * x + 3 * y;
y = y + 1;
```

### Решение

Все варианты ниже дают одинаковые конечные значения `x`, `y`, `z` при обычных целочисленных значениях без переполнения.

**Вариант 1 — оператор запятой:**

```cpp
(x = x + 1, z = z + 2 * x + 3 * y, y = y + 1);
```

**Вариант 2 — сокращённые присваивания и инкременты:**

```cpp
(++x, z += 2 * x + 3 * y, ++y);
```

**Вариант 3 — префиксный и постфиксный инкременты в одном выражении:**

```cpp
z += 2 * ++x + 3 * y++;
```

В последнем варианте `++x` сразу увеличивает `x`, а `y++` подставляет прежнее значение `y`, после чего увеличивает `y`. Изменяются разные переменные, поэтому конфликтующих изменений одной переменной здесь нет.

## Задание 3

### Условие

Рассмотрите следующий фрагмент программы. Он заполняет вектор из 10 элементов единицами.

```cpp
std::vector<int> x(10);
for (int i = 0; i < 10;)
    x[i++] = 1;
```

Перепишите ее так, чтобы в третьей строке использовался префиксный инкремент, но результат ее работы не изменился.

```cpp
std::vector<int> x(10);
for (...)
    x[++i] = 1;
```

### Решение

```cpp
std::vector<int> x(10);
for (int i = -1; i < 9;)
    x[++i] = 1;
```

Начинаем с `i = -1`. При первом `++i` индекс становится `0`, при последнем — `9`. Поэтому заполняются те же десять элементов `x[0]` ... `x[9]`.

## Задание 4 

### Условие

Почему присваивание `(++x)=y` является синтаксически правильным, а `(x++)=y` — нет? Запишите текст сообщения об ошибке, переведите и объясните его.

### Решение

```cpp
int x = 1, y = 7;
(++x) = y;   // Допустимо: x станет равен 7.
// (x++) = y; // Ошибка компиляции.
```

Префиксный `++x` возвращает **lvalue**, то есть обозначает саму переменную `x`, значение которой разрешено изменять. Постфиксный `x++` возвращает прежнее значение **как prvalue**, а не переменную, в которую можно записать `y`.

Пример сообщения компилятора C++ :

```text
error: lvalue required as left operand of assignment
```

Перевод: «В левой части присваивания требуется lvalue». Это означает, что слева от `=` должен находиться изменяемый объект, а результат `x++` таким объектом не является.

## Задание 5 

### Условие

Программисты на Python для обмена значений двух переменных часто пишут строку

```python
a, b = b, a
```

Проверьте, будет ли аналогичная строка на C++ (с точкой с запятой в конце) являться синтаксически правильной? Будет ли она обменивать значения переменных? Как в языке C++ вычисляется это выражение?

### Решение

```cpp
int a = 1, b = 2;
a, b = b, a;
// После выполнения: a == 1, b == 2.
```

Строка **синтаксически корректна, но значения не меняет местами**. Поскольку приоритет `=` выше приоритета оператора `,`, выражение разбирается как

```cpp
(a), (b = b), (a);
```

Части последовательно вычисляются, но результат `a` отбрасывается, а `b = b` присваивает переменной её же значение.

В C++ для обмена следует написать:

```cpp
#include <utility>
std::swap(a, b);
```

## Задание 6

### Условие

Проверьте работу следующего фрагмента программы

```cpp
std::string s;
for (int i = 0; i < 1000000; i++)
    s += 'a';
std::cout << s.size();
```

Измените третью строку на

```cpp
s = s + 'a';
```

Изменится ли что-нибудь в ее работе? Объясните результат.

### Решение

**В обоих случаях вывод — `1000000`.** Каждая итерация добавляет один символ `a`, всего итераций миллион.

Разница — в способе формирования строки:

- `s += 'a'` изменяет существующую строку. При увеличении её ёмкости память выделяется лишь время от времени. Обычно этот способ работает значительно быстрее.
- `s = s + 'a'` сначала создаёт результат конкатенации, затем присваивает его `s`. В обычной реализации приходится многократно формировать новые строки и переносить ранее записанные символы. Поэтому расход памяти и время выполнения **могут быть заметно больше**.

Точное время зависит от компилятора, оптимизации и реализации `std::string`; утверждать конкретное ускорение нельзя. Для первого способа при многократном добавлении сложность обычно амортизированно близка к `O(n)`, для второго без устранения временных копий — к `O(n²)`.

## Задание 7

### Условие

Как работает следующая программа? Как зависит результат от исходного значения?

```cpp
int x;
std::cin >> x;
x-- > 0 && x-- > 0 && x-- > 0 && x-- > 0 && x-- > 0;
std::cout << x;
```

### Решение

Запись `x-- > 0` — это `(x--) > 0`: сравнение **старого** значения `x` с нулём и последующее уменьшение `x` на один. У `&&` правая часть вычисляется, только если предыдущая истинна.

Для корректно введённого целого `x₀`, при отсутствии переполнения:

| Исходное `x₀` | Сколько раз выполнится `x--` | Итог |
|---|---:|---:|
| `x₀ < 0` | 1 | `x₀ - 1` |
| `0 ≤ x₀ ≤ 4` | `x₀ + 1` | `-1` |
| `x₀ ≥ 5` | 5 | `x₀ - 5` |

Например: `x₀ = 0` → `-1`; `x₀ = 2` → `-1`; `x₀ = 5` → `0`; `x₀ = 8` → `3`; `x₀ = -2` → `-3`.

**Исключение:** если исходное значение равно минимально допустимому `int` (`INT_MIN`), первый декремент вызывает переполнение знакового типа, то есть неопределённое поведение.

## Задание 8 

### Условие

Какое число выводит следующий фрагмент программы? Посчитайте результат без использования вычислительной техники. Отчет должен содержать процесс вычислений.

```cpp
int s = 0;
for (int i = 0, j = 5; i + j <= 16; (i < j ? i : j)++)
    (s += i) += j;
std::cout << s;
```

### Решение

Тело цикла `(s += i) += j` сначала прибавляет к `s` значение `i`, а затем `j`. То есть за один проход добавляется `i + j`.

После каждого прохода выражение `(i < j ? i : j)++` увеличивает меньшую переменную: если `i < j`, увеличивается `i`, иначе — `j`.

Посчитаем вручную по проходам:

| Проход | `i` | `j` | `i + j` | `s` после прохода |
|---:|---:|---:|---:|---:|
| 1 | 0 | 5 | 5 | 5 |
| 2 | 1 | 5 | 6 | 11 |
| 3 | 2 | 5 | 7 | 18 |
| 4 | 3 | 5 | 8 | 26 |
| 5 | 4 | 5 | 9 | 35 |
| 6 | 5 | 5 | 10 | 45 |
| 7 | 5 | 6 | 11 | 56 |
| 8 | 6 | 6 | 12 | 68 |
| 9 | 6 | 7 | 13 | 81 |
| 10 | 7 | 7 | 14 | 95 |
| 11 | 7 | 8 | 15 | 110 |
| 12 | 8 | 8 | 16 | 126 |

В следующий раз получим `i = 8`, `j = 9`, сумма `17 > 16`, и цикл закончится.

**Ответ: `126`.** Проверка компиляцией дала тот же результат, но расчёт выше выполнен по шагам.

## Задание 9 

### Условие

Рассмотрите следующую программу. Предполагается, что на вход подается некоторый индекс в массиве — число от нуля до девяти и значение, которое надо записать по этому индексу.

```cpp
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];
std::cout << x[i];
```

Проверьте работу этой программы на различных компиляторах. Найдите два компилятора (можно проверить онлайн компиляторы), на которых эта программа будет давать различные ответы при одинаковом вводе. Как это объяснить?

### Решение

Для проверки использовал ввод:

```text
3 42
```

Результаты **моей проверки** на доступных компиляторах:

| Компилятор | Режим | Вывод |
|---|---|---|
| GCC 14.2.0 | C++14 (`-O0`) | `42` |
| Clang 17.0.0 | C++14 (`-O0`) | `42` |
| GCC 14.2.0 | C++17 (`-O0`) | `42` |
| Clang 17.0.0 | C++17 (`-O0`) | `42` |

**Два реально проверенных компилятора с различными ответами найти не удалось.** Не следует выдавать гипотетическое различие за результат эксперимента.

Объяснение идеи задания: до C++17 порядок вычисления двух частей оператора `>>` не был гарантирован. Поэтому в старых реализациях выражение `x[i]` могло использовать прежнее `i = 0` до чтения нового индекса; сочетание чтения и изменения `i` также не было безопасно с точки зрения старых правил последовательности вычислений. Для указанного ввода можно представить ситуацию, когда значение `42` записывается в `x[0]`, а затем программа печатает `x[3]`, то есть `0` (вектор изначально заполнен нулями). Такой вывод **не подтверждён приведёнными испытаниями**.

Начиная с **C++17** для `E1 >> E2` установлено вычисление левой части до правой, в том числе при записи оператора в обычной операторной форме для потоков. Поэтому сначала происходит `std::cin >> i`, затем вычисляется индекс `x[i]`, и при вводе `3 42` результат **однозначно равен `42`**.

Чтобы код был понятен и не зависел от старых правил, лучше разделить ввод на две строки:

```cpp
std::cin >> i;
std::cin >> x[i];
std::cout << x[i];
```

В реальной программе также нужно проверить успешность ввода и границы индекса (`0 <= i && i < 10`).
