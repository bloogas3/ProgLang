## Задание 1. Четыре способа объявления Pi (2)

Рассмотрим следующую программу на C++.

```cpp
#include <iostream>
#include <cmath>

int main() {
    double x = 0;
    const auto Pi = std::acos(0) * 2;
    std::cout << Pi << std::endl;
    return 0;
}
```

Проверьте четыре способа объявления `Pi`.

```cpp
const auto Pi = std::acos(0) * 2;
constexpr auto Pi = std::acos(0) * 2;
const auto Pi = std::acos(x) * 2;
constexpr auto Pi = std::acos(x) * 2;
```

Проверьте, какие варианты работают и в каких значение `Pi` вычисляется при компиляции.

### Решение

Я по очереди ставил каждое объявление в программу. Вместе все четыре строки ставить нельзя, потому что имя `Pi` повторяется.

| Вариант | Результат проверки | Почему |
| --- | --- | --- |
| `const auto Pi = std::acos(0) * 2;` | Работает | Значение можно вычислить, менять его потом нельзя |
| `constexpr auto Pi = std::acos(0) * 2;` | Работает | Значение вычисляется при компиляции |
| `const auto Pi = std::acos(x) * 2;` | Работает | Для `const` можно использовать обычную переменную `x` |
| `constexpr auto Pi = std::acos(x) * 2;` | Ошибка | Обычная переменная `x` не подходит для такого вычисления |

У работающих вариантов получилось:

```text
3.14159
```

В первом и третьем вариантах значение менять нельзя, но `const` не требует вычислять его заранее. `auto` тут означает, что тип определяется автоматически. Получился тип `double`.

Во втором варианте `constexpr` требует вычислить число при компиляции. У меня этот вариант собрался. Четвёртый вариант выдал ошибку, потому что `x` — обычная переменная.

Ещё я записал число напрямую, без `acos`. Такой вариант работает:

```cpp
#include <iostream>

int main() {
    constexpr double Pi = 3.14159265358979323846;
    std::cout << Pi << '\n';
}
```

**Вывод.** Первые три варианта у меня работают, четвёртый выдаёт ошибку. Во втором варианте значение вычисляется при компиляции. В первом и третьем `const` только запрещает менять значение после создания.

## Задание 6. Обмен длинных строк (2)

Рассмотрим следующий фрагмент программы. Эта программа 1000000 раз обменивает значения двух длинных строк с использованием третьей строки. Проверьте, насколько быстро она работает.

```cpp
string a(100000, 'a');
string b(100000, 'b');
for (int i = 0; i < 1000000; i++) {
    string c(a);
    a = b;
    b = c;
}
std::cout << a[0] << b[0];
```

Попробуйте использовать для обмена значений строк функцию `swap`. Проверьте, изменилось ли время работы. В чем ошибка исходной программы? Исправьте исходную программу, чтобы ускорить ее работу. Изменения не должны затрагивать общий вид программы (присваивания, использование временной переменной).

### Решение

Я проверил три варианта в одной программе: сначала копирование, потом `swap`, потом перемещение через `std::move`.

```cpp
#include <chrono>
#include <iostream>
#include <string>
#include <utility>

int main() {
    std::string a(100000, 'a');
    std::string b(100000, 'b');

    // 1. Обмен с копированием.
    auto start = std::chrono::steady_clock::now();
    for (int i = 0; i < 1000000; i++) {
        std::string c = a;
        a = b;
        b = c;
    }
    auto finish = std::chrono::steady_clock::now();
    double seconds = std::chrono::duration<double>(finish - start).count();
    std::cout << "copy: " << seconds << " s; " << a[0] << b[0] << '\n';

    // 2. Обмен с помощью swap.
    start = std::chrono::steady_clock::now();
    for (int i = 0; i < 1000000; i++) {
        a.swap(b);
    }
    finish = std::chrono::steady_clock::now();
    seconds = std::chrono::duration<double>(finish - start).count();
    std::cout << "swap: " << seconds << " s; " << a[0] << b[0] << '\n';

    // 3. Обмен с перемещением.
    start = std::chrono::steady_clock::now();
    for (int i = 0; i < 1000000; i++) {
        std::string c = std::move(a);
        a = std::move(b);
        b = std::move(c);
    }
    finish = std::chrono::steady_clock::now();
    seconds = std::chrono::duration<double>(finish - start).count();
    std::cout << "move: " << seconds << " s; " << a[0] << b[0] << '\n';
}
```

Собирал и запускал так:

```bash
g++ -O2 task06.cpp -o task06.exe
./task06.exe
```

| Способ обмена | Время, с | Итоговые первые символы |
| --- | ---: | --- |
| Копирование через третью строку | 6.33666 | `ab` |
| `a.swap(b)` | 0.0022843 | `ab` |
| Перемещение через третью строку | 0.005558 | `ab` |

Время относится к одному запуску. На другом компьютере оно может быть другим.

Первый вариант работает правильно, но при каждом обмене три раза копирует длинный текст. Поэтому он медленный. `swap` обменивает строки без копирования всех символов. В третьем варианте `std::move` позволяет передать уже выделенную память другой строке. Временная строка и два присваивания при этом остались.

После каждого цикла получилось `ab`. Число обменов чётное, поэтому строки вернулись на свои места. Перед следующим циклом создавать их заново не надо.

После перемещения строку можно использовать снова, но считать её обязательно пустой нельзя. В этой программе в неё сразу записывается другое значение.

**Вывод.** Я убрал лишнее копирование, и обмен стал намного быстрее. Если надо оставить общий вид исходного кода, подходит третий вариант с `std::move`.

## Задание 7. Строки и id

Рассмотрим программу на языке Python.

```python
a = 'Hello world'
print(a, id(a))
b = a
print(b, id(b))
a += ' and goodbye'
print(a, id(a))
print(b, id(b))
```

Объясните ее работу. В какой момент создавались строки? Что означает значение, возвращенное функцией `id`?

### Решение

Я получил такой вывод. Вместо длинных чисел записал `ID1` и `ID2`, потому что сами числа зависят от запуска:

```text
Hello world ID1
Hello world ID1
Hello world and goodbye ID2
Hello world ID1
```

Сначала `a` ссылается на строку `Hello world`. После `b = a` у этой строки два имени, копии нет. Поэтому первые два идентификатора одинаковые.

Когда выполняется `a += ' and goodbye'`, получается новая строка. Теперь `a` ссылается на неё, а `b` остаётся со старой строкой. `id` — это номер объекта, который не меняется, пока объект существует. У двух разных живых объектов номера разные. В CPython это адрес в памяти, но в других реализациях может быть иначе. После удаления объекта его номер может использоваться снова.

**Вывод.** `b = a` не копирует строку. Добавление текста к `a` даёт другую строку, поэтому значение `b` осталось прежним.

## Задание 9. Создание 2600 переменных (2)

Напишите программу на языке Python, которая создаст 2600 переменных с именами от `a0` до `a99`, от `b0` до `b99` и так далее, от `z0` до `z99`. Присвойте всем переменным различные значения от 1 до 2600.

### Решение

Я сделал два цикла, чтобы не писать 2600 присваиваний вручную.

```python
value = 1
for letter in 'abcdefghijklmnopqrstuvwxyz':
    for number in range(100):
        name = letter + str(number)
        globals()[name] = value
        value += 1

print(a0, a99, b0, z99)
print(value - 1)
```

Результат:

```text
1 100 101 2600
2600
```

Первый цикл берёт букву, второй — номер от 0 до 99. Из них собирается имя. Через `globals()[name]` я создаю переменную с таким именем. После каждой записи значение увеличивается на 1.

**Вывод.** Получилось `26 * 100 = 2600` переменных. Значения идут по порядку от 1 до 2600 и не повторяются.

## Задание 12. Функция sumint (*4)

Напишите функцию `sumint` на Python, которая найдет сумму всех целочисленных переменных, определенных в среде Idle. Например:

```pycon
>>> a = 10
>>> b = 1.5
>>> c = 15
>>> d = 'hello'
>>> sumint()
25
```

### Решение

Я перебрал значения переменных и добавил к сумме только целые числа.

```python
def sumint():
    total = 0
    for value in globals().values():
        if type(value) is int:
            total += value
    return total


a = 10
b = 1.5
c = 15
d = 'hello'
print(sumint())
```

Результат:

```text
25
```

Функцию определял прямо в IDLE вместе с примером. `globals()` даёт словарь переменных этой среды, а `.values()` — их значения. В сумму попали 10 и 15. Дробное число и строка не попали.

Проверка `type(value) is int` также не учитывает `True` и `False`, потому что их тип — `bool`. Переменные внутри самой функции в сумму не входят. Если одно число записано в две переменные, оно учитывается два раза.

Пример нужно проверять в чистом сеансе. Если остались целочисленные переменные от других заданий, они тоже попадут в сумму.

**Вывод.** Функция возвращает сумму целых значений из словаря переменных. Для исходного примера получилось `10 + 15 = 25`.

## Задание 13. Расположение переменных в памяти (*10)

В языке C++ для получения информации о расположении переменной в памяти можно использовать оператор взятия адреса `&`. Адрес можно интерпретировать, как беззнаковое длинное число с использованием `reinterpret_cast`.

```cpp
reinterpret_cast<unsigned long long>(&t);
```

Здесь `t` имя некоторой переменной. Напишите несколько примеров, чтобы проверить, как размещаются переменные в памяти. В частности можно рассмотреть следующие вопросы.

- Если объявить несколько переменных различных типов в одном блоке, то на какую величину отличаются их адреса? Соотносится ли эта величина с размером переменной в байтах. Проверьте, имеются ли различия на разных уровнях оптимизации.
- Если имеется несколько блоков, расположенных последовательно, то могут ли переменные в разных блоках иметь одинаковые адреса? Проверьте разные уровни оптимизации.
- Объявите несколько переменных типа (`std::string`) и попробуйте заносить в них строки различной длины. Изменяется ли размер переменной, вычисленный с использованием `sizeof`? Изменяется ли расположение переменной? Попробуйте объяснить полученные результаты.

### Решение

Я разделил проверку на три небольшие программы.

#### 1. Разные типы

```cpp
#include <iostream>

int main() {
    char c = 'A';
    int i = 10;
    double d = 2.5;
    long long n = 100;

    std::cout << "c: " << reinterpret_cast<unsigned long long>(&c)
              << ", size: " << sizeof(c) << '\n';
    std::cout << "i: " << reinterpret_cast<unsigned long long>(&i)
              << ", size: " << sizeof(i) << '\n';
    std::cout << "d: " << reinterpret_cast<unsigned long long>(&d)
              << ", size: " << sizeof(d) << '\n';
    std::cout << "n: " << reinterpret_cast<unsigned long long>(&n)
              << ", size: " << sizeof(n) << '\n';
}
```

Здесь я вывел адрес и размер каждой переменной. Потом посчитал расстояния между адресами: из большего числа вычел меньшее.

#### 2. Два блока подряд

```cpp
#include <iostream>

int main() {
    {
        int x = 1;
        std::cout << "x: " << reinterpret_cast<unsigned long long>(&x) << '\n';
    }
    {
        int y = 2;
        std::cout << "y: " << reinterpret_cast<unsigned long long>(&y) << '\n';
    }
}
```

Я сравнил напечатанные адреса `x` и `y`. Первая переменная уже закончила существовать, когда создаётся вторая.

Эти программы собирал с `-O0` и `-O2`. Например, первую так:

```bash
g++ -O0 task13_1.cpp -o task13_1_O0.exe
g++ -O2 task13_1.cpp -o task13_1_O2.exe
./task13_1_O0.exe
./task13_1_O2.exe
```

#### 3. Строки разной длины

```cpp
#include <iostream>
#include <string>

int main() {
    std::string a = "abc";
    std::string b(1000, 'x');
    std::string c(100000, 'y');

    std::cout << "sizes: " << sizeof(a) << ' '
              << sizeof(b) << ' ' << sizeof(c) << '\n';

    std::cout << "before: " << reinterpret_cast<unsigned long long>(&a)
              << ", data: " << reinterpret_cast<unsigned long long>(a.data())
              << ", length: " << a.size() << '\n';

    a = std::string(100000, 'z');

    std::cout << "after: " << reinterpret_cast<unsigned long long>(&a)
              << ", data: " << reinterpret_cast<unsigned long long>(a.data())
              << ", length: " << a.size() << '\n';
    std::cout << "sizeof after: " << sizeof(a) << '\n';
}
```

Я создал три строки разной длины. Для первой сравнил адрес и размер до и после увеличения текста. Третью программу тоже проверил с `-O0` и `-O2`.

Получились такие результаты:

| Наблюдение | `-O0` | `-O2` |
| --- | ---: | ---: |
| Расстояние между адресами `c` и `i`, байт | 7 | 1 |
| Расстояние между адресами `i` и `d`, байт | 8 | 4 |
| Расстояние между адресами `d` и `n`, байт | 8 | 8 |
| Совпали числовые адреса переменных последовательных блоков | 0 | 1 |
| `sizeof(a)`, `sizeof(b)`, `sizeof(c)`, байт | 32, 32, 32 | 32, 32, 32 |
| Адрес объекта строки `a` сохранился | 1 | 1 |
| `sizeof(a)` сохранился | 1 | 1 |
| Адрес буфера `a.data()` изменился | 1 | 1 |
| Длина строки `a` после присваивания | 100000 | 100000 |

В таблице 1 означает «да», 0 — «нет». Сами адреса между запусками меняются.

Размеры `char`, `int`, `double` и `long long` у меня получились 1, 4, 8 и 8 байт. Расстояния между адресами не всегда равны этим размерам. Компилятор может оставлять промежутки и менять порядок размещения. Поэтому с разными настройками результаты отличаются.

В двух отдельных блоках адреса при `-O2` совпали, а при `-O0` нет. Это нормально: `x` и `y` существуют в разное время, и одно место можно использовать ещё раз. Но компилятор не обязан каждый раз делать одинаково.

У всех трёх строк `sizeof` равен 32 байтам, хотя длина текста разная. Это размер самого объекта строки. Длинный текст хранится отдельно. После увеличения строки адрес самого объекта остался тем же, а адрес её символов изменился. Длину текста показывает `.size()`, а адрес символов — `.data()`.

**Вывод.** Размещение переменных зависит от компилятора и настроек. У строки размер самого объекта и длина текста — разные вещи. При увеличении текста может поменяться его место в памяти, но не адрес самой переменной строки.
